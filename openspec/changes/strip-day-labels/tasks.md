## 1. Card: day labels and dividers

The day labels sit in a new grid row under the time labels (brainstorm D1). Each day on the axis is one segment, from its start, or the axis's left edge for the day in progress there, to the next day's start or the axis's right end. Its label sits at the segment's left, so the pinned label needs no special case (D2). These tasks share `card/src/strip.ts` and `card/src/pierpressure-card.ts`, so they run in order.

- [x] 1.1 [easy] A day-label formatter in `card/src/strip.ts`, beside `clock` and `timeFormat`, writes an instant's date in Home Assistant's time zone as `<weekday> <day> <month>`, such as `Sat 31 Oct`. It reads only numeric parts from `Intl.DateTimeFormat` with `numberingSystem: "latn"`, and maps the weekday and month through fixed lists `Mon` … `Sun` and `Jan` … `Dec`. That keeps every browser on `Sep`, where `en-GB` gives `Sept` in current ICU. An unknown time zone falls back to the browser's, as `timeFormat` does. Tests: 2026-09-03T00:00:00Z in `UTC` reads `Thu 3 Sep`; 2026-10-31T15:00:00Z in `Asia/Tokyo` reads `Sun 1 Nov`; an `ar-EG` browser still reads `Sat 31 Oct` (brainstorm D3; spec night-card "A day label names the weekday, the day and the month") (verify: `cd card && npx vitest run test/strip.test.ts`) (✓ `cd card && npx vitest run test/strip.test.ts` passed)
- [x] 1.2 [medium] `buildStrip` returns `days`: one entry per calendar day that overlaps the axis, in order, each with `from` and `to` (the segment's ends, clamped to the axis), its label `text`, and `start` only when the day starts strictly between the axis's start and end. A day starts at the first quarter-hour instant whose date differs from the instant before, found by stepping quarter hours as `timeLabels` does. So `America/Santiago` on 2026-09-06 starts at 2026-09-06T04:00:00Z, which reads 01:00. Tests cover each scenario of "The axis carries day labels under its time labels" and "A day starts at the first instant of its date": UTC, Tokyo with no day start, an axis that starts as a day starts, polar night and Santiago (brainstorm D2, D5; spec night-card) (verify: `cd card && npm run typecheck && npx vitest run test/strip.test.ts`) (✓ `cd card && npm run typecheck && npx vitest run test/strip.test.ts` passed)
- [x] 1.3 [medium] The card draws the days as a `.track.days` row directly under `.track.times`, with the same font size and secondary text colour. Each day is a `.day` element placed by `left` and `width` in percent of the axis, with `data-from`, `data-to` and its label text. `grid-template-rows` gains one row. The lines' overlay still ends at the bottom of the Temperature chart, and the time labels are unchanged. A new `card/test/days.test.ts` renders the card through the test harness and reads the day labels in order (brainstorm D1; spec night-card "The axis carries day labels under its time labels") (verify: `cd card && npm run typecheck && npx vitest run test/days.test.ts test/strip.test.ts`) (✓ `cd card && npm run typecheck && npx vitest run test/days.test.ts test/strip.test.ts` passed)
- [x] 1.4 [medium] The card draws a `.dividers` overlay in the axis column that spans exactly the time-label row and the day-label row, with one `.divider` per day that has a `start`, placed by `left` in percent and carrying `data-at`. A divider is 1 px wide, solid, in `var(--divider-color)`, and has no `title`, `aria-label` or `data-tip`, so it has no hover text and a tap on it closes any open box. Tests: one divider at 2026-11-01T00:00:00Z for the UTC axis; none for the Tokyo axis; the overlay's `grid-row` starts at the time-label row and spans 2 rows (brainstorm D4; spec night-card "A divider marks each day's start") (verify: `cd card && npm run typecheck && npx vitest run test/days.test.ts`) (✓ `cd card && npm run typecheck && npx vitest run test/days.test.ts` passed)
- [x] 1.5 [medium] A day label that does not fit whole in its `.day` segment is hidden, not cut off or moved, and its divider still shows. In the stylesheet, `.day` is a 16 px tall, `overflow: hidden`, `display: flex`, `flex-wrap: wrap` box. Its first child is a zero-width spacer 16 px tall, then the `white-space: nowrap` label. A label wider than its segment wraps onto a second flex line below the clipped box. The rule is the same in both layouts. happy-dom does not lay out text, so tests read the rules with `cardStyles()` and check each `.day`'s spacer and label. Task 3.1 checks the hiding by eye (brainstorm D2, D7; spec night-card "A day label shows only when it fits whole") (verify: `cd card && npx vitest run test/days.test.ts`) (✓ `cd card && npx vitest run test/days.test.ts` passed)
- [x] 1.6 [easy] Panning redraws the day labels and dividers for the new axis. A pan of 24 hours from the opening axis 2026-10-31T16:30:00Z to 2026-11-01T08:25:00Z in `UTC` shows `Sun 1 Nov` at the left edge and `Mon 2 Nov` from 2026-11-02T00:00:00Z, with one divider there. The test goes in `card/test/pan.test.ts` (spec night-card "Everything on the strip pans together") (verify: `cd card && npx vitest run test/pan.test.ts`) (✓ `cd card && npx vitest run test/pan.test.ts` passed)
