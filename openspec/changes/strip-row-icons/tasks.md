## 1. Card: icons, labels, legend and taps

These tasks all touch `card/src/pierpressure-card.ts`, so they run in order.

- [x] 1.1 [medium] Each of the fourteen rows' labels and the Moon up lane's label holds an icon from a new `card/src/icons.ts`, drawn from the draft set in issue #332: a `.icon` span with `role="img"` and the row's name as `title` and `aria-label`, around an `aria-hidden` 16 px SVG in `currentColor`, followed by the name in an `aria-hidden` `.name` span. A target lane's label holds no icon: a `.rank` span `<n>` with `title` and `aria-label` `Target <n>`, then a `.name` span `Target <n>` that is not `aria-hidden`. Tests that read a label's text read `.label .name`, and still see `Sun altitude` to `Rain chance` and `Target 1` (design Decisions 3 and 4; spec night-card "Each row, the Moon up lane and each key entry has an icon", "Hovering over an icon or a rank number shows its name") (verify: `cd card && npm run typecheck && npx vitest run test/icons.test.ts test/rows.test.ts test/strip.test.ts test/targets.test.ts`) (✓ `npm run typecheck` and `npx vitest run test/icons.test.ts test/rows.test.ts test/strip.test.ts test/targets.test.ts` passed, 251 tests)
- [x] 1.2 [easy] Each Temperature chart key entry shows its colour swatch, then its icon (`title` and `aria-label` `Temperature` or `Dew point`), then its name in an `aria-hidden` `.name` span, then its message when it has one; the key still reads `Temperature`, then `Dew point`, and `Not found` still shows beside `Dew point` when its sensor is missing (design Decision 7; spec night-card "The Temperature chart's lines are orange and green", "A Temperature chart line that cannot draw says why") (verify: `cd card && npm run typecheck && npx vitest run test/chart.test.ts test/icons.test.ts`) (✓ `npm run typecheck` and `npx vitest run test/chart.test.ts test/icons.test.ts` passed, 69 tests)
- [x] 1.3 [medium] The Temperature chart's °C labels are in the chart's `.track`, in a `.scale` overlay at its left edge, and `.chart-label` holds only the key. Each `.step` keeps its `data-celsius`, its `top` and its end-label shift. The stylesheet gives `.scale` `pointer-events: none` and `color: var(--secondary-text-color)`, places each `.step` from the left, and gives it a backing of `var(--card-background-color)`. The existing scale tests pass with the new place, and a pan leaves the labels unchanged. happy-dom does not honour `pointer-events`, so a test checks the `.scale` rule and that a tap on the hour from 16:00 shows its text; task 3.1 checks a tap through a label by hand (design Decision 6; spec night-card "The Temperature chart labels each 5 °C step", "The °C labels leave the chart's hours readable and tappable", "Everything on the strip pans together") (verify: `cd card && npx vitest run test/chart.test.ts test/pan.test.ts`) (✓ `npx vitest run test/chart.test.ts test/pan.test.ts` passed, 131 tests)
- [x] 1.4 [medium] The stylesheet makes `ha-card` a named inline-size container and holds a container query for a card narrower than 450 px. Outside the query, `.rank` and `.legend` are `display: none`. Inside it, each label's and key entry's `.name` is `display: none`, and `.rank` and `.legend` show. No viewport media query and no card option picks the layout. Tests read the rules with `cardStyles()` (design Decisions 1 and 2; spec night-card "The layout follows the card's own width", "A card 450 px or wider shows each icon beside its label", "A card narrower than 450 px shows only the icons") (verify: `cd card && npx vitest run test/icons.test.ts`) (✓ `npx vitest run test/icons.test.ts` passed, 30 tests)
- [x] 1.5 [medium] A `<ul class="legend">` follows `.strip` in the card. It has one entry per drawn row, then `Moon up`, `Temperature` and `Dew point`, each with the same icon as its label but `aria-hidden`, with no `title` and no `data-tip`. It ends with a `Target rank` entry when the strip has a target lane: a `.rank` span, `aria-hidden`, holding the rank of the strip's first target lane, then a `.name` span `Target rank`, with no icon. With Cloud range and Target 1 the entries read `Sun altitude` … `Rain chance`, `Moon up`, `Temperature`, `Dew point`, `Target rank`. Without Cloud range there is no `Cloud range` entry. With no target lane, the last entry is `Dew point` (design Decision 5; spec night-card "The strip's legend names each icon") (verify: `cd card && npx vitest run test/icons.test.ts`) (✓ `npx vitest run test/icons.test.ts` passed, 43 tests)
- [x] 1.6 [medium] Each icon and rank number is a tap item keyed `label:<place>`: a row key, `moon_up`, `chart:<line key>` or `target_<n>`. A tap on the Seeing icon shows `Seeing`.
